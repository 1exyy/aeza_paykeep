# Aéza PayKeep (Invoice Keeper)

Сервис напоминаний о регулярных платежах для команд: аренда, хостинг, подписки, сервисы. Он хранит платежи и их периоды, заранее напоминает о сроках в Telegram, на почту и по webhook, а отметить оплату можно в вебе, в Telegram Mini App или кнопкой «Оплачено» прямо в напоминании.

В одном сервисе работает несколько команд: у каждой свои администратор, пользователи, платежи и каналы уведомлений, и данные команд не пересекаются. Новые команды заказывают через бота заявок, а супервайзер их одобряет.

## Возможности

### Пользователь команды
- **Платежи.** Список периодов со статусами «ожидает», «просрочен», «оплачен», «оплачен с опозданием». Есть фильтры по статусу и ответственному; у пользователя по умолчанию выбраны его платежи.
- **Отметка оплаты.** Оплату можно отметить, отменить или исправить дату. Свою отметку можно поставить кнопкой «Оплачено» в напоминании в Telegram.
- **Вложения.** К каждому периоду можно приложить чек (JPEG, PNG, PDF) или ссылку.
- **Сводка.** Суммы «начислено / оплачено / не оплачено / просрочено» за выбранный период по каждой валюте (RUB, USD, EUR). Кнопка «Подробнее» показывает платежи этого периода.
- **Календарь и бюджет.** Месяц по дням, плановые суммы на месяц или год, включая ещё не созданные периоды.
- **Выгрузка календаря.** Месяц или год в `.csv` (Excel, Google Таблицы) или `.ics` (Google, Apple, Outlook календари). Повторный импорт `.ics` обновляет события, а не дублирует их.
- **Свой пароль.** «Ещё → Сменить пароль», нужен текущий пароль.

### Администратор команды
Всё, что может пользователь, и ещё:
- **Регулярные платежи.** Создание, изменение и прекращение платежей. Периодичность: ежедневно, еженедельно, ежемесячно, каждые N дней или разово. Ответственные: один, несколько или все пользователи.
- **История платежа.** Все периоды и все действия с платежом.
- **Пользователи.** Добавление и удаление. Можно указать Telegram (`@username` или ID) и задать временный пароль: пользователь сменит его при входе.
- **Настройки уведомлений.** Чат Telegram, почта (SMTP), webhook. У каждого канала есть кнопка «Проверить». Изменения применяются без перезапуска.
- **Журнал действий и доставки уведомлений.** Кто, что и когда сделал; ушло ли каждое уведомление.

### Супервайзер
Одна учётная запись на весь сервис, вне команд. У него одна вкладка — «Заявки на команды»:
- **Принять.** Создаются команда, её администратор с временным паролем и каналы уведомлений из заявки. Бот заявок присылает заявителю данные для входа.
- **Отклонить.** С причиной, которую бот передаёт заявителю.

### Уведомления
- **Каналы.** Напоминание о сроке уходит в чат Telegram команды, в личные сообщения ответственным, на почту и по webhook. Дополнительно можно подключить Slack-совместимый webhook.
- **Когда.** Напоминание приходит за 3 дня до срока, не раньше предыдущего срока: у ежедневного платежа — в день оплаты. Отправка начинается с 09:00, каждое напоминание приходит один раз.
- **Webhook.** Получает события о напоминаниях, оплате и отмене оплаты, создании и прекращении платежа. Запрос подписан HMAC-SHA256.

### Боты
- **Бот напоминаний.** Присылает напоминания с кнопкой «Оплачено». `/start` открывает Mini App. Команда `/chatid` в группе отвечает ID этого чата.
- **Бот заявок.** Пошаговая заявка на новую команду: название, логин администратора, чат для напоминаний (бот проверяет, что может туда писать), по желанию почта. Сообщение с паролем SMTP бот сразу удаляет.

## Быстрый запуск

Нужен только Docker с Compose v2.

```bash
docker compose up --build
```

Откройте <http://localhost:8080>. Swagger API — <http://localhost:8080/api/v1/docs>.

Демо-учётки (создаются автоматически вместе с тестовыми платежами):

| Кто | Команда | Логин | Пароль |
|---|---|---|---|
| Администратор | `aeza` | `admin` | `admin-demo-123` |
| Пользователи | `aeza` | `anna`, `boris` | `anna-demo-123`, `boris-demo-123` |
| Супервайзер | *оставить пустым* | `supervisor` | `supervisor-demo-123` |

Эти пароли — только для локального запуска. На сервере используйте свои (см. [Развёртывание](#развёртывание-на-сервере)).

Остановить: `docker compose down`. Удалить данные вместе с базой: `docker compose down -v`.

Без бота Telegram сервис работает полностью, но напоминания уходят только в настроенные каналы. Как подключить бота — в разделе [Telegram](#telegram).

## Как устроено

```
браузер / Telegram Mini App
          │  HTTPS
     caddy (по желанию) ─► web (nginx + собранный фронт) ─► /api/ ─► api (FastAPI)
                                                                     │
                                         worker ◄──── PostgreSQL ────┘
                          (периоды, напоминания, отправка, оба бота)
```

| Сервис | Что делает |
|---|---|
| `db` | PostgreSQL 16, все данные |
| `api` | REST API `/api/v1`; при старте применяет миграции и создаёт админа и супервайзера из `.env` |
| `worker` | раз в минуту создаёт периоды и планирует напоминания, раз в 5 секунд отправляет, держит long polling обоих ботов |
| `web` | собирает фронт и отдаёт его через nginx, проксирует `/api/` |
| `caddy` | HTTPS-сертификат для домена (профиль `https`) |

- **Хранение.** Данные лежат в volume `pgdata`, вложения — в `attachments`.
- **Контракт.** API описан в [docs/api/openapi.yaml](docs/api/openapi.yaml), его же показывает Swagger.

## Настройка

- **Где.** Значения по умолчанию для локального запуска лежат в [backend/defaults.env](backend/defaults.env). Свои значения задаются в `backend/.env` (шаблон — [backend/.env.example](backend/.env.example)) и перекрывают значения по умолчанию.
- **Применить.** После правки выполните `docker compose up -d api worker`.

| Переменная | Зачем |
|---|---|
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | администратор первой команды |
| `DEFAULT_TEAM_NAME` | название первой команды (по умолчанию `aeza`) |
| `SUPERVISOR_LOGIN`, `SUPERVISOR_PASSWORD` | супервайзер; пусто — супервайзера нет |
| `PUBLIC_BASE_URL` | адрес сервиса, например `https://invoice.example.com` |
| `APP_TZ_OFFSET` | часовой пояс системы, например `+03:00` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | бот напоминаний |
| `TELEGRAM_CHAT_ID` | чат напоминаний первой команды (можно задать и во вкладке настроек) |
| `MINIAPP_URL` | адрес Mini App для кнопки в боте |
| `APPLY_BOT_TOKEN` | бот заявок на новые команды |
| `SMTP_*`, `EMAIL_RECIPIENTS` | почта первой команды (или во вкладке настроек) |
| `WEBHOOK_URL`, `WEBHOOK_SECRET` | webhook первой команды (или во вкладке настроек) |
| `DEV_MODE` | демо-режим: сдвиг «сегодня» и мгновенный запуск задач в Swagger |

**Важно про каналы:**
- Значения каналов из `.env` действуют только для первой команды. Новые команды настраивают каналы в заявке или во вкладке «Настройки уведомлений».
- Если хост блокирует порты почты 25/465/587, используйте почтовый сервис с портом 2525.

**Важно про пароли:**
- Пароли админа и супервайзера из `.env`, изменённые в приложении, переживают перезапуск.
- Чтобы сбросить пароль, поменяйте его значение в `.env`.

## Telegram

1. **Бот напоминаний.** Создайте бота у @BotFather. Впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (без `@`).
2. **Чат команды.** Добавьте бота в группу (в канал — администратором) и напишите в группе `/chatid`. Полученный ID (вида `-100…`) укажите во вкладке «Настройки уведомлений» или в `TELEGRAM_CHAT_ID`.
3. **Mini App.** В @BotFather выполните `/setmenubutton` с адресом сервиса и `/setdomain` с доменом. Нужен HTTPS.
4. **Личные напоминания и кнопка «Оплачено».** Администратор указывает пользователю Telegram в карточке пользователя. Пользователь один раз пишет боту `/start`, и бот его узнаёт.
5. **Бот заявок.** Создайте второго бота у @BotFather и впишите его токен в `APPLY_BOT_TOKEN`. Ссылку на него можно давать тем, кто хочет завести команду.

Токены ботов храните только в `backend/.env` на сервере.

## Развёртывание на сервере

Пошаговая инструкция для нового VPS, с HTTPS на своём домене или без домена: [deploy/VPS.md](deploy/VPS.md).

Кратко:

```bash
./deploy/vps/install-docker.sh
./deploy/vps/configure.sh invoice.example.com
docker compose --profile https up -d --build
```

Без домена: `./deploy/vps/configure.sh --tunnel` и `docker compose --profile tunnel up -d --build` (временный адрес trycloudflare).

`configure.sh` генерирует пароли базы, администратора и супервайзера и показывает их один раз. Они остаются в `backend/.env`.

Бэкап базы и вложений: `./deploy/vps/backup.sh`.

## Разработка

### Фронт (React, TypeScript, Vite, RTK Query)
Нужен Node.js 22.12+ и npm.

```bash
npm ci
npm run dev:demo
```

- **`dev:demo`.** Весь интерфейс на вымышленных данных, без бэкенда. Вход: команда `demo`, логин `admin`, `anna` или `boss` (супервайзер), пароль `demo`.
- **`dev` с настоящим API.** Запустите `docker compose up --build`. В `.env.local` укажите `DEV_API_PROXY_TARGET=http://localhost:8080`, затем `npm run dev`. Чтобы проходила проверка `Origin`, поставьте в `backend/.env` `PUBLIC_BASE_URL=http://localhost:5173` и выполните `docker compose up -d api`.
- **Проверки:** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`, `npm run test:e2e:demo`.

### Бэкенд (Python 3.12, FastAPI, SQLAlchemy 2, Alembic, aiogram 3)
Нужны [uv](https://docs.astral.sh/uv/) и PostgreSQL.

```bash
docker compose --profile test up -d db-test
cd backend
uv sync
TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5433/invoice_keeper_test uv run pytest -q
uv run ruff check . && uv run mypy app
```

API без Docker: `uv run uvicorn app.main:app --reload --port 8000` (нужен локальный PostgreSQL и `DATABASE_URL` в `backend/.env`, шаблон — `backend/.env.example`). Worker: `uv run python -m app.worker`.

### Структура
| Где | Что |
|---|---|
| `src/` | фронт: `app` (роутер, оболочка), `pages`, `features`, `entities`, `widgets`, `shared`; демо-данные в `src/mocks` |
| `backend/app/api` | эндпоинты |
| `backend/app/services` | бизнес-логика: расписания, напоминания, outbox, команды, заявки |
| `backend/app/channels` | Telegram, почта, webhook, Slack-совместимый канал |
| `backend/app/worker` | фоновые задачи и оба бота |
| `backend/migrations` | миграции Alembic |
| `deploy/` | nginx, Caddy, скрипты и инструкция для VPS |
